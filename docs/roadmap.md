# 現状とロードマップ

## 現行の0.9系

通常の起動・一覧表示・静止中は必要な読み込みと描画だけを行う。明示された3Dプレビュー、詳細表示、サムネイル生成、印刷準備に処理を割り当て、中止後はリソースを解放する。

| 操作 | 現在の動作 |
| --- | --- | --- |
| 起動と監視 | 保存済みSQLiteカタログから一覧を開く。初回の監視通知を登録に再利用し、監視で確認できなかった登録パスだけを個別照合する。 |
| 3Dプレビュー | 3MFと大きいSTLの解析を中止可能なワーカーで実行する。WebGLは形状確定後に初期化し、静止時は描画を停止する。 |
| 大きい3MF | 3D読み込みに失敗したときは、ZIPから範囲読み込みした対応画像を表示する。明示した詳細読み込みに保存済みの予算を適用する。 |
| サムネイル | 画像をSQLiteのBLOBに保存し、画面には必要な画像だけをバイナリ配信する。一括生成は1つの作業用レンダラーで1件ずつ処理する。 |
| 配布 | ビルド済み画面と重複していた依存ライブラリを除き、実行時に必要な依存ファイルとライセンスを同梱する。 |

### v0.9.1の変更

- 3MFの頂点をインデックスで共有し、面の見え方と角ごとの色を保持する。
- 3Dビューの視点調整と再読み込みを明示的な操作に変更する。
- サムネイル生成履歴の永続化をメインプロセスの起動処理から分離する。

色付き立方体のテストでは、同じ12三角形を36個から8個の頂点に減らした。座標・色・法線・インデックスの配列の合計は1,296バイトから336バイト。これはテストメッシュの計測で、アプリ全体の使用メモリはモデルや処理段階によって変わる。

## v1.0の確定仕様

Nineはモデルと使い方を管理するハブと、選んだモデルを目的に合う処理先へ渡すルーターを担う。

### 原本の保持とフォーク履歴

- 改名、移動、コピー、モデルの編集はすべてフォークとして扱う。親の版と原本を保持し、操作結果に新しい版を割り当てる。監視で見つけた移動・改名を確定する場合も、新しい版を親に結び付ける。移動先に独立した登録があれば、その設定と履歴も保持する。
- 履歴には版ID、親の版ID、操作の種類、日時、各版の内容を参照できる情報を保持する。「一つ前に戻す」は直前の親を選び直す操作とし、現在の枝も履歴に残す。復元に必要なファイル内容と設定値を保存する。
- プリセットの編集結果は既定でフォークする。既存プリセットの上書きは明示操作で行う。その場合も直前の値を履歴から参照できるようにする。派生出力は、使用したモデルとプリセットの版に結び付ける。
- 整理の操作は原本と履歴を保持する。現行のゴミ箱への移動は、この要件と整合するように見直す。監視先で外部アプリが直接上書き・削除した原本を復元できる範囲は、原本をいつ保全するかと合わせて決める。

合格条件は、親から複数の派生版を作成し、再起動後もそれぞれの親をたどり、直前のモデル内容・設定値へ戻れること。親の内容と別の枝を保持する。プリセットは通常保存と明示上書きの両方で確認する。

### スライサーへの引き渡し

- ユーザーがモデルと行き先を選ぶ。Nineは選ばれたモデルまたは必要な派生ファイルを、そのスライサーに渡す。STL・STEP・3MFは選んだ版のファイルを使い、OpenSCADは選んだ版とパラメータから引き渡し用STLを生成する。
- Nineの完了点は、対象ファイルを付けた起動・オープン要求を指定したスライサーへ渡せた時点。スライス、素材やプリンタの選択、印刷送信、送信結果はスライサー側が担当する。画面は引き渡しの成否を伝え、以降の操作はスライサーで行うことを案内できる。

合格条件は、STL・STEP・3MFおよびSCAD由来STLを意図したスライサーに渡せること。元ファイルの内容を保持し、引き渡しの失敗や中止を表示できること。

### 割り込みとジョブの優先順位

Nine内の処理が競合した場合は、**読み込み中止 → 別モデル参照 → スライサーへの引き渡し**の順に優先する。

1. **読み込み中止**は、進行中の読み込みや解析に直ちに中止を伝える。中止した処理の結果は破棄し、処理に使ったリソースを解放する。
2. **別モデル参照**は、古いプレビューの読み込みを中止して、最新の選択を表示する。軽量モードでは登録情報とサムネイルを先に出し、3Dはユーザーが指示したときに読み込む。
3. **スライサーへの引き渡し**は、上位の要求に処理枠を譲る。待機中も、指示時に選んだモデルの版と行き先を引き渡し対象として保持する。引き渡しが済んだ処理はスライサー側が担当する。

一括サムネイル生成などのバックグラウンド処理は、これらの操作に処理枠を譲る。すでに保存できたサムネイルは保持する。

合格条件は、中止と参照切り替えを連続しても古いプレビュー結果が表示されず、引き渡しは指定時のモデルの版と行き先で実行されること。

### エージェント向けのライブラリ操作

MCPは、エージェントが登録済みモデルを探し、用途に合うファイルを受け取るための窓口とする。提供する操作は検索・閲覧、ファイルコピー、STL出力の3つ。

| 操作 | 動作 |
| --- | --- |
| 検索・閲覧 | 登録モデルを検索し、候補から目的の版を選べるようにする。選択に必要なモデル情報、保存済みサムネイル、SCADプリセットを参照できる。 |
| ファイルコピー | 指定した版のファイルを元の形式のままコピーする。原本を保持し、新しいコピーを親の版に結び付ける。 |
| STL出力 | 指定したモデルの版からSTLを生成し、使用したモデルと設定の版を履歴に残す。初期実装は現行のOpenSCAD出力を利用し、プリセットとパーツを指定できるようにする。 |

コピーと出力は、元の版と設定を保持する。保存先の指定方法と実行前確認の要否は、MCPのファイル操作を実装する前に確定する。

合格条件は、検索結果から指定した版のコピーまたはSTLを取得でき、出力から親の版と使用した設定をたどれること。

## v1.0のリリース合格条件は保留

リリースに必要な操作ルート、最低動作環境、想定する登録件数と代表モデル、起動・検索・初回3D表示の待ち時間は、残っている改善を進めた段階で確定する。当面は既存の動作テストとv0.9.0の測定記録を改修前後の比較に使う。

## v1リリース後の完全刷新

まず、モデル管理、フォーク履歴、ジョブの優先順位、モデルの引き渡しをv1のリリースとしてまとめる。完全刷新はその後のマイルストーンとする。製品表記、画面の文言、保存先と形式、連携の契約は刷新後の仕様として決める。

刷新で引き継ぐ互換性は、原本と保持対象となる派生モデルの保全に限る。切り替えは旧環境から新環境への一方向とする。モデルの保全方法は、v1で管理方法が固まった段階で定義する。切り替え前後で、対象モデルのデータが揃い、新環境で開けることを検証する。
