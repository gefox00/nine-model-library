# Nine Model Library

Windows用のローカル3Dファイルライブラリ。STL / STEP・STP / 3MF / OpenSCAD を一覧表示できます。OpenSCADのモデルは公開パラメータを調整し、3D表示やSTL出力ができます。

開発を引き継ぐときは [AGENTS.md](AGENTS.md) と [設計・データの流れ](docs/architecture.md) を参照してください。

## 起動

`起動.cmd` をダブルクリックしてください。配布版の実行ファイルは `release/win-unpacked/Nine Model Library.exe` です。実行ファイルを移動するときは **win-unpackedフォルダ全体** を移動します。配布版の実行にNode.jsは不要です。

アプリはローカルで動作します。元ファイルを移動・変換・アップロードせず、現在の保存場所を参照します。Bambu Studioに渡す場合も元ファイルをそのまま開きます。

## 基本操作

- **監視フォルダを追加**: サブフォルダを含めて登録し、ファイルの追加・更新・削除・復帰を自動反映。フォルダのドラッグ＆ドロップでも登録できます。監視はアプリ起動中に動き、次の起動時にも再スキャンします。
- **ファイルを追加 / ドロップ**: 個別ファイルを登録。個別登録のみのファイルは、起動時と「再スキャン」で更新確認します。常時更新するならその保存フォルダを監視に追加してください。
- **3Dビュー**: 左ドラッグで回転、右ドラッグで移動、ホイールで拡大縮小。`F` で全体表示。斜め・正面・上面・右面、ワイヤーフレーム、グリッド、自動回転に対応。
- **ライブラリ**: 検索（`Ctrl+F`）、形式フィルタ、名前・更新日・サイズ順、グリッドとリスト、お気に入り、タグ、メモ。タグはカンマ区切りで入力して保存します。
- **サムネイル**: モデルを初めて開いたときに生成・保存します。元ファイルの更新時には作り直します。
- **モデルを右クリック**: プレビュー、選んだ1件のサムネイル生成、指定フォルダへのコピー、Bambu Studioで開く、削除を選べます。コピー先に同名ファイルがあれば中止します。「削除」は確認後に元ファイルをWindowsのゴミ箱へ移し、登録を外します。
- **サムネイル生成**: ライブラリ上部のボタンから、検索やフィルタに関係なく全登録を対象に1件ずつ生成します。「未生成のみ」が初期値で、既存画像も更新したいときは「すべて再生成」を選びます。開始時のプレビューメモリ設定を使い、ファイル不在はスキップ、読み込みエラーや90秒超過は失敗の詳細に記録して次へ進みます。中止しても保存済みの画像は残り、「未生成のみ」で続きから処理できます。
- **Bambu Studioで開く**: 自動検出したインストール済みBambu Studioへ渡します。検出できない場合は「設定と連携」で `bambu-studio.exe` を指定してください。
- **プレビューメモリ**: 「設定と連携」→「プレビューメモリ」で0.5〜32 GiBを指定できます。プリセットと数値入力に対応。「設定を保存」は次のモデル読み込みから反映し、「保存して再読み込み」は現在のモデルを再試行します。再起動は不要で、設定は次回起動後も保持します。
- **登録解除**: ライブラリからだけ削除し、監視での自動再登録を抑制します。「ファイルを追加」またはファイルのドロップで再登録できます。元ファイルは消しません。
- **監視解除**: フォルダの監視を解除しても、登録済みモデルは残ります。

## OpenSCAD

`.scad` ファイルを登録して選ぶと、インストール済みのOpenSCADで元ファイルを計算し、形状を表示します。OpenSCADが未検出なら「設定と連携」で実行ファイルを指定できます。元ファイルと同じフォルダを基準にするので、相対指定の `include` や `import` もOpenSCAD側で解決されます。

「公開パラメータ」の値を変更してプレビューし、その設定でSTLへ出力できます。元のSCADは書き換えません。パラメータ欄はメインファイルの先頭にある数値、真偽値、文字列、数値ベクトルのリテラルをサポートします。`[Hidden]` や式で算出される内部値は表示しません。入力した値は現在のモデルを開いている間に使います。

| STL出力モード | 出力内容 |
| --- | --- |
| 現在のモデル | パラメータ欄の値で1ファイル |
| 指定したパーツ | パーツ切り替えの選択肢を1つ指定 |
| 選択したパーツ | チェックした選択肢を1ファイルずつ |
| 全パーツ | パーツ候補を1ファイルずつ。組立・分解・確認用と判別できる表示候補は除く |

パーツ出力は、たとえば `part = "assembly"; // [assembly:Assembly, base:Base, lid:Lid]` のように、モデル自身が公開パラメータの選択肢を持つ場合に使えます。別名のパラメータもパーツ切り替えとして選べます。形状を解析して自動分割する機能ではありません。複数ファイルを出すときは、保存先を選んで順番に生成します。同名のSTLがあればその項目は失敗として記録します。

## 対応範囲

| 形式 | 表示 |
| --- | --- |
| STL | ASCII / binary。単位情報がないためmmとして表示 |
| SCAD | インストール済みOpenSCADで形状を計算し、3D表示。公開パラメータの編集とSTL出力に対応 |
| STEP / STP | OpenCascade WASMで表示用メッシュに変換。基本色・面色対応。編集用CADカーネルではありません |
| 3MF | メッシュ、部品構造、配置、単位、基本色・頂点色、Bambu方式の分割モデル参照 |
| 形状のない3MF | 内蔵画像があれば静止プレビュー表示。3D回転や寸法表示は不可 |

Bambu / Orca独自のペイント色、テクスチャ、複合マテリアル、スライス済みツールパスの再現は未対応です。表示上の制約を画面に示し、元ファイルの印刷設定は保持します。複数プレートのモデルは、3MFの元の配置でまとめて表示します。

プレビューメモリの初期値は2 GiB。このとき入力256 MiB、単一XML128 MiB、展開合計384 MiB、300万三角形が上限です。設定を増やすと上限も広がり、設定画面で実際の値を確認できます。たとえば8 GiBでは入力1 GiB、単一XML256 MiB、展開合計1.5 GiB、1,200万三角形になります。

この設定は**読み込み制限を調整するためのメモリ予算**で、実際のRAM使用量を指定値以下に強制制限するものではありません。解析中は予算を超える場合があります。OSから取得した搭載RAMと空きRAMも設定画面に表示します。

解析方式による実装上限は、入力1 GiB、単一XML256 MiB、展開合計2 GiB、2,400万三角形です。予算を増やしてもこの上限は残り、超過時には設定で解除できない旨を表示します。STEP変換は180秒で打ち切り、別モデルへの切り替えで中止します。大きなSTL/3MFでは読み込み中に画面が一時的に重くなる場合があります。プレビュー上限を超えるモデルも登録とBambu Studioへの受け渡しは可能です。

## 保存データ

通常は `%APPDATA%/Nine Model Library/library.json` に登録情報・監視フォルダ・タグ・メモ・サムネイル・Bambuパスを保存します。JSONは同一ディレクトリ内で一時ファイルから置換します。破損時は元データを上書きせず起動エラーを表示します。バックアップするときはアプリを終了してこのファイルをコピーしてください。

同じパスの二重登録は防ぎます。同一内容でも別の保存場所なら別モデルとして扱います。名前変更・移動は旧パスが不在になり、新パスを別モデルとして登録します。

## 開発・機能追加

Node.jsとnpmを用意し、このフォルダで実行します。

```text
npm ci
npm run dev
npm test
npm run build
npm run package
```

`npm run dev` はViteとElectronをまとめて起動します。`npm run package` はWindows用のフォルダ形式アプリを作ります。署名は付けていません。

| 場所 | 責務・追加の入口 |
| --- | --- |
| `shared/formats.json` | 登録可能な拡張子と形式表示名 |
| `shared/preview-memory.json` | メモリ予算の範囲、標準値、倍率計算の基準と実装上限 |
| `shared/preview-memory.cjs`, `src/formats/preview-memory.js` | main/rendererの読み込み上限計算。同値であることをテスト |
| `src/components/MemorySettings.jsx` | メモリ設定UI、予算別の上限表示 |
| `src/formats/index.js` | 形式アダプタの登録。`loadModel(bytes, context)` に統一 |
| `src/formats/stl.js`, `step.js`, `three-mf.js` | 形式ごとの読み込みと制限 |
| `public/occt/step-worker.js` | STEP変換。UIとは別のWorkerで実行 |
| `src/components/ModelViewer.jsx` | カメラ、照明、描画、操作、サムネイル |
| `src/components/ThumbnailBatchPanel.jsx` | 一括生成の開始・中止・進捗と結果 |
| `electron/thumbnail-batch.cjs`, `src/thumbnail-worker.js` | 順次生成、1件ずつの読み込みと描画、結果の保存 |
| `src/App.jsx`, `src/styles.css` | ライブラリ画面、検索、詳細、設定 |
| `electron/library.cjs` | ファイル管理、監視、保存、登録解除 |
| `electron/main.cjs` | ウィンドウ、ダイアログ、Bambu起動、IPC |
| `electron/preload.cjs` | 画面に公開する限定API (`window.nine`) |

新形式は専用アダプタを作り、`shared/formats.json` と `modelAdapters` に追加します。戻り値は `{ object: THREE.Object3D, unit: 'mm', warnings: string[], metadata?: object }`、入力は `ArrayBuffer` と `{ filename, signal, limits }` です。`loadModel()` で受け取った `memoryBudgetMiB` から `limits` を計算してアダプタへ渡すので、固定値を追加せずその値で入力や描画量を検査してください。座標はZ-up、寸法はmmに統一してください。形状のない画像専用結果は `object: null, previewImage: dataURL, metadata: { previewOnly: true }` です。

新しい外部アプリとの連携はmain側に追加し、preloadで専用APIを公開します。画面側にNode.js権限はありません。プラグインを実行時にインストールする方式ではなく、責務を分けたソースコードに機能を追加して再ビルドする構造です。

## 検証

`npm test` は実ファイル監視、重複登録、永続化、除外と再登録、破損データ保持、各形式の寸法、部品配置、色、単位変換、循環参照・不正形状、実STEP変換を検証します。

`npm run build` の後、`node scripts/smoke.mjs` で3形式の表示、検索、タグ・メモ・お気に入り、ファイル監視、再起動後の保存を実画面で確認できます。検証にはテスト用モデルと独立したプロファイルを使用し、結果は `output/playwright/` に保存します。

`node scripts/smoke-memory.mjs` はメモリ設定の保存と上限エラーからの再読み込み、`node scripts/smoke-thumbnails.mjs` は一括サムネイル生成、中止、再起動後の復元、`node scripts/smoke-context-menu.mjs` はモデルの右クリック操作を検証します。各スクリプトに `--packaged` を付けると配布用EXEを対象にします。

OpenSCADをインストールした環境では、`node scripts/smoke-scad.mjs` でSCAD登録、サムネイル、公開パラメータ編集、4種類のSTL出力を確認できます。

主な依存: Electron / React / Three.js / chokidar / fflate / occt-import-js。各依存のライセンスは配布フォルダ内のライセンス文書と `node_modules` 内の各パッケージを参照してください。
